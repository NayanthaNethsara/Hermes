### Benefits of PostgreSQL with `pgvector`

1. **Unified Storage Layer**:
   - Replaces fragmented ChromaDB files and multiple SQLite databases with a single relational database.
   - Houses ingestion tracking (`ingestion_tracker`), document metadata, and multimodal chunks in one schema.
2. **Dense Vector Search**:
   - Stores 1024-dimensional embeddings from Voyage Multimodal 3.5 using `vector(1024)`.
   - Supports HNSW indexing for rapid cosine similarity (`<=>`) queries.
3. **Built-in Sparse Keyword Search**:
   - Uses PostgreSQL full-text search (`tsvector` with GIN indexing and `ts_rank_cd`) or `pg_trgm` for exact proper noun matching, eliminating the need for a separate BM25 engine.
4. **Hybrid Search Execution**:
   - Dense vector retrieval and full-text keyword retrieval can be executed within the same database connection and fused via Reciprocal Rank Fusion (RRF).

1. core/ — Infrastructure & Global Configuration
config.py:

Use pydantic-settings (BaseSettings) to read and validate environment variables: DATABASE_URL (PostgreSQL connection string), VOYAGE_API_KEY, GCP_PROJECT_ID, GCP_LOCATION, ASSETS_DIR, and score cutoff thresholds.

database.py:

Configure asyncpg engine and async session factory via SQLAlchemy 2.0.

Register the pgvector extension upon startup: CREATE EXTENSION IF NOT EXISTS vector;.

logging.py:

Initialize structured logging (structlog or standard library formatted for JSON) to trace document ingestion progress and agent node execution.

exceptions.py:

Define domain-specific exceptions (e.g., RetrievalThresholdError, DocumentParsingError) with FastAPI exception handlers.

2. data/ — Local File Storage
raw_archive/: Local mirror of the 415 corpus files (PDF, DOCX, MD, TXT, scanned images). Excluded from Git.

extracted_assets/: Output directory for cropped figures, diagrams, and tables extracted by the parser. Mounted by FastAPI as a static assets endpoint (/assets/...) so images can be served directly to the frontend.

3. ingestion/ — Layout Parsing & Indexing Pipeline
schemas.py:

Define Pydantic models for raw document metadata (doc_id, file_hash, source_category, epistemic_weight, file_path, page_number).

Define schemas for extracted elements (TextChunk, ExtractedFigure, ExtractedTable).

parser.py:

Integrate IBM Docling (DocumentConverter).

Perform layout analysis to identify text blocks, tables, and figures.

Extract bounding box coordinates, crop figure/table regions using Pillow, save .png files to data/extracted_assets/, and retain local path links.

chunker.py:

Split document text into semantically cohesive units (512–1024 tokens) while preserving parent section headings and associated figure file references.

embedder.py:

Batch calls to the Voyage AI multimodal embedding endpoint (voyage-multimodal-3.5).

Generate vectors for text chunks with interleaved image data.

Implement retries with exponential backoff (tenacity) to respect rate limits.

4. retrieval/ — Two-Stage Search Core
schemas.py:

Define SearchQuery, SearchResultChunk, and RankedResult Pydantic models.

vector_store.py:

Manage the PostgreSQL table schema:

id (UUID)

doc_id (VARCHAR)

file_hash (VARCHAR)

content (TEXT)

embedding (VECTOR(1024/1536)) with an HNSW index using cosine distance

tsv (TSVECTOR) for full-text search

metadata_payload (JSONB) holding file path, category, and image references

Execute Hybrid Search via Reciprocal Rank Fusion (RRF) directly in SQL, combining vector similarity (<=>) and keyword matching (ts_rank).

reranker.py:

Accept broad retrieval output (Top 30–50 candidates) and call Voyage AI rerank-2.5.

Enforce a strict relevance score cutoff (e.g., minimum score of 0.50). Drop candidate chunks falling below threshold to prevent model hallucinations.

router.py:

FastAPI endpoints (POST /retrieval/search) for direct retrieval queries without invoking agents.

5. agents/ — State Machine & Multi-Track Reasoning (LangGraph)
llm.py:

Initialize Google Cloud Vertex AI integration (ChatVertexAI using Gemini 1.5 Pro) with strict temperature settings (0.0–0.2).

state/base.py & state/models.py:

Define strongly typed state objects via typing.TypedDict or Pydantic:

root_query: Initial user prompt.

search_queries: Pending sub-queries to execute.

retrieved_context: List of verified chunks with relevance scores.

figures: List of local image paths for Track 1A.

facts: Key-value registry of extracted facts with credibility weights for Track 1C.

iteration_count and max_iterations to prevent infinite execution loops.

nodes/ (Action Components):

planner.py: Deconstructs complex inquiries into discrete search sub-queries.

retriever.py: Invokes retrieval/vector_store.py and reranker.py to populate state context.

evaluator.py: Compares newly retrieved facts against prior evidence; performs source credibility arbitration (e.g., official codex overriding folklore).

visualizer.py: Resolves bounding-box image paths to full asset URLs for Track 1A payload attachment.

synthesizer.py: Formulates the final response and forces structured output via Pydantic (answer_text, referenced_figures, citations).

graphs/ (Workflow Wiring):

multimodal_1a.py: Linear DAG (retriever -> visualizer -> synthesizer).

investigator_1c.py: Iterative state graph (planner -> retriever -> evaluator -> conditional edge looping back to retriever or advancing to synthesizer).
